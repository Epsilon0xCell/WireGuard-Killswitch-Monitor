WireGuard Kill Switch for macOS

A bash script that creates a kill switch for WireGuard VPN on macOS using PF (Packet Filter). While it runs, traffic is passed only when the WireGuard interface is present with the expected MTU; otherwise all traffic is blocked, so a dropped VPN does not leak traffic onto the local network.

Open the repo Usage

The one rule

Make sure your VPN uses MTU 1280: the script treats any other MTU as "VPN not connected". The loaded rules are deliberately simple: block all plus pass in and pass out on the VPN interface while it is up, block all alone otherwise. Each state change writes the complete ruleset to a temp file and loads it with a single pfctl -f call, because a pfctl load replaces the whole main ruleset. pfctl failures are printed and the state is retried on the next check rather than reported as success.

How it watches

Detectionautomatic: the interface with MTU 1280, the WireGuard UDP listen port visible in netstat, and an assigned IP, with a wg show interfaces fallback and a utun4 final fallback
Re-checkevery 2 seconds (a CHECK_INTERVAL constant at the top of the script); status messages print on state changes only, not on every check
RequirementsmacOS, WireGuard configured with MTU 1280 and ListenPort 51820 (or set WIREGUARD_PORT), and administrative privileges: the script calls pfctl through sudo

Usage

git clone https://github.com/Epsilon0xCell/WireGuard-Killswitch-Monitor.git
cd WireGuard-Killswitch-Monitor
chmod +x killswitch.sh
./killswitch.sh

./killswitch.sh --help prints a short usage text and exits 0 without touching pf. The script takes no other arguments: an unknown argument exits 2, and so does a WIREGUARD_PORT that is not a number from 1 to 65535 or a VPN_INTERFACE value with characters outside letters, digits, _, ., and -.

VPN_INTERFACEWireGuard interface name. When set, detection is skipped and this interface is monitored directly. When unset, the script auto-detects and falls back to utun4.
WIREGUARD_PORTWireGuard server listen port used during detection (default: 51820).

The README also walks through automatic startup under launchd, with the daemon file at /Library/LaunchDaemons/com.wireguard.killswitch.plist.

Cleanup, and the SIGKILL gap

Stop it with Ctrl+C. The cleanup function runs on SIGINT and SIGTERM and uses sudo pfctl -F all and sudo pfctl -d to flush the PF rules and disable PF, restoring normal internet access. Cleanup disables PF rather than restoring a previous ruleset. If the script is killed with SIGKILL (kill -9), no cleanup can run and the last loaded rules stay in place; run those two pfctl commands by hand in that case.

leak_test.py

A small companion monitor, also macOS only. It polls https://ipinfo.io/ip roughly every 0.1 seconds plus request time, prints the current public IP, and uses macOS notifications (osascript) to warn you. It treats the first public IP that differs from your local address as the "VPN active" state; if the public IP later equals your local address, it raises a "POTENTIAL VPN LEAK DETECTED" notification. That is a heuristic based only on comparing the two addresses, not proof of a leak. The service response is validated as an IP address before it is used anywhere. python3 leak_test.py --help prints usage and exits 0; any other argument exits 2.

The tests

python3 -m unittest discover -s tests

18 tests, all passing when last run on a Linux host. The killswitch tests run the real killswitch.sh against stub pfctl, ifconfig, netstat, wg, sudo, and sleep commands on PATH, so they check the control flow, the single ruleset load, the retry after a failed load, the argument and port checks, and the cleanup calls. They do not check real PF behavior on macOS, and the pass has not been run on a Mac: confirming the loaded rules on a real Mac with sudo pfctl -sr in both the connected and blocked states is still an open check, not something these tests settle. The leak_test.py tests mock the ipinfo.io request, the hostname lookup, and osascript.
