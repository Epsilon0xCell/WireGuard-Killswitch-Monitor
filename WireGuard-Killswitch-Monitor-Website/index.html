WireGuard-Killswitch-Monitor

killswitch.sh is a bash script for macOS that uses PF, the packet filter, to keep traffic moving only while a WireGuard interface is present and reporting MTU 1280. It rechecks every 2 seconds and prints a message only when the state changes.

Panel one: the job

One ruleset per state

While the MTU 1280 condition holds, the script loads one ruleset: block all plus pass in and pass out on the VPN interface. When the condition fails, it loads block all on its own. The recheck interval is a fixed CHECK_INTERVAL constant of 2 seconds in the script.

Panel two: detection

How the interface is found

With VPN_INTERFACE unset, the script looks among utun interfaces for MTU 1280, checks that something on the machine listens on the WireGuard UDP port in netstat output, and checks that the interface holds an IP address. Failing that, it tries wg show interfaces, and failing that it falls back to utun4. With VPN_INTERFACE set, detection is skipped and that named interface is watched directly.

Hut note: the script's own comments admit the weak point. The netstat port test is not tied to the candidate interface, so MTU and address do the narrowing, and none of it proves the listening port belongs to that interface.

Panel three: running

Requirements and configuration

Requirements are macOS, WireGuard set to MTU 1280 and ListenPort 51820, and sudo, since pfctl is called through sudo. Usage is ./killswitch.sh after chmod +x. --help or -h prints usage and exits 0; any other argument exits 2. WIREGUARD_PORT is accepted only as a number from 1 to 65535, default 51820.

chmod +x killswitch.sh
./killswitch.sh

Each state change writes a complete ruleset to a temp file and loads it with a single pfctl -f call: a load replaces the whole main ruleset, so loading rule by rule would discard all but the last. Failed loads are reported and retried on the next check, never announced as success.

Panel four: exit ⚑

Cleanup flushes and disables PF

Ctrl+C or SIGTERM runs cleanup, which flushes the rules with sudo pfctl -F all and disables PF with sudo pfctl -d, restoring normal access rather than restoring any earlier ruleset.

If the script is ended with SIGKILL, no cleanup can run and the last rules stay loaded until the two pfctl commands are run by hand or the machine restarts.

The launchd plist lives at /Library/LaunchDaemons/com.wireguard.killswitch.plist, with RunAtLoad and KeepAlive, and logs at /var/log/killswitch.log and /var/log/killswitch.error.log. KeepAlive relaunches a stopped script while the daemon stays loaded.

Panel five: the companion

leak_test.py, a heuristic

Labelled a heuristic: a matching address is treated as a possible leak, not as proof of one.

leak_test.py, also macOS only, polls ▲▲▲https://ipinfo.io/ip roughly every tenth of a second plus request time, compares the public address with the local one, validates the reply as an IP address, and raises a macOS notification through osascript when the public address later matches the local one. Its install line is pip install -r requirements.txt, its only listed requirement being requests.

Panel six: test record

18 tests, Linux host

18 tests run against stub pfctl, ifconfig, netstat, wg, sudo, and sleep commands, plus mocked requests for the leak test, all passing on a Linux host when last run. Real PF behaviour on a Mac is still unchecked, and sudo pfctl -sr in both states is named as an open check.

WireGuard-Killswitch-Monitor: a watch kept in bad weather, one complete ruleset per state, and a clean stand down on exit.
